# 계산 명세 — 이 문서 하나로 모든 숫자가 재현된다

**이 문서가 이 묶음에서 가장 중요하다.** 화면을 예쁘게 만드는 건 시간이 해결하지만,
숫자가 틀리면 심사에서 그 자리에서 끝난다.

맨 끝의 **§9 검산표**대로 값이 나오면 계산부는 옳게 짠 것이다. 먼저 §9 를 보고 목표를
확인한 뒤 위로 올라와도 된다.

---

## 1. 총비용 3분해

```
총비용(USD) = 기본운임 + 탄소비용(EU ETS) + 전쟁위험보험료 [+ 적하보험료(CIF만)]
```

세 항목은 **서로 다른 것에 비례한다.** 이걸 뭉개면 안 된다.

| 항목 | 무엇에 비례하나 | 인코텀즈 영향 |
|---|---|---|
| 기본운임 | 항로 기준운임 × **운임 배율**(`mult`) | 금액 불변, **부담 주체만** 바뀜 |
| 탄소비용 | 항로 **실거리** × **단위 배율**(`unit`) × EUA 시세 | 운임을 내는 쪽을 따라감 |
| 전쟁위험보험료 | 선체가치 × **단위 배율** × **항로별 요율** | 운임을 내는 쪽을 따라감 |
| 적하보험료 | (화물가액+운임+탄소) × 110% × 요율 | **CIF 에서만** 발생 |

> ⚠ **인코텀즈 배율을 곱하지 마라.** 예전에 `기본운임 × (EXW 0.85 / FOB 0.92 / CIF 1.05 /
> DDP 1.15)` 를 썼다가 폐기했다. 이 배율 넷은 전부 가정치였고 "CIF 가 FOB 보다 14% 비싸다"는
> 근거가 어디에도 없었다. 인코텀즈는 **금액을 바꾸지 않고 누가 내는지를 정한다.**

## 2. 탄소비용 (EU ETS)

### 2-1. 배출량

```
연료소모량(t)   = 항로거리(nm) ÷ (속력(kn) × 24) × 일일연료소모량(t/일)
CO2 배출량(t)   = 연료소모량 × 배출계수(EF)
단위당 배출량(t) = CO2 배출량 ÷ 선박 적재능력
```

| 상수 | 값 | 근거 |
|---|---|---|
| 선박 적재능력 | 10,000 TEU | 1만 TEU급 가정 |
| 속력 | 18 knots | |
| 일일 연료소모량 | 180 t/일 | |
| 배출계수 EF | **3.114 tCO₂/t연료** | IMO 2020 가이드라인 · VLSFO |

계산을 줄이면 **1 nm 당 연료 0.4166667 t** 이다(180 ÷ 432).

### 2-2. 비용

```
과금대상 CO2(t)  = 단위당 배출량 × ETS 적용범위 계수
탄소비용(EUR)    = 과금대상 CO2 × EUA 시세(EUR/tCO2) × 단위 배율
탄소비용(USD)    = 탄소비용(EUR) × 환율(USD/EUR)
```

**ETS 적용범위 계수 = 0.5** — 이걸 빠뜨리면 탄소비용이 **정확히 2배**로 나온다.

| 항해 | 제출 대상 |
|---|---|
| EEA 역내 ↔ EEA 역내 | 배출량의 100% |
| **EEA 역외 ↔ EEA 역내** | **배출량의 50%** ← 부산 → 함부르크가 여기 |

단계적 도입(2024년 40% / 2025년 70% / 2026년 이후 100%)은 2026년 기준 100%이므로
실효계수는 **0.5** 다. 두 계수를 혼동해서 곱하지 마라 — 0.5 × 1.0 = 0.5 다.

> ⚠ 탄소비용을 **반올림해서 저장하지 마라.** 이 값은 표시용이면서 동시에
> "EUR/tCO₂ → USD/화물단위" 환산 배율의 분자로 쓰인다. $62.77 을 $62 로 깎으면
> 가격 구간 전체가 1.2% 밀린다(실제로 밴드가 56.99~68.07 대신 56.73~67.76 으로 나왔다).
> 반올림은 **표시 함수에서만** 한다.

## 3. 전쟁위험보험료

```
전쟁위험보험료(USD) = 단위당 선체가치 × 단위 배율 × 항로별 요율
```

| 상수 | 값 |
|---|---|
| 선체가치 / TEU (컨테이너) | $9,000 (1만 TEU급 선체 약 $9,000만 가정) |
| 선체가치 / CEU (PCTC) | $12,000 (1만 CEU급 약 $1.2억 가정) |

**항로별 요율**

| 항로 | 요율 | 근거 |
|---|---|---|
| A 싱가포르 경유 | 0.1% | 후티 사정권 밖 저위험 (Al Jazeera · S&P Global Platts) |
| B 홍해 직항 | **0.75%** | 2026.7.20 후티 대사우디 봉쇄 선언 후 급등 (Reuters · Insurance Journal) |
| D 콜롬보 경유 | 0.6% | **A·B 사이 보간 추정치 — 특정 기사 인용 아님. 자체 추정이라고 밝힐 것** |
| C 희망봉 우회 | **0%** | 위험구역 미경유 · 해당 없음 |

C 의 0% 가 이 제품의 핵심 장면이다 — 운임은 가장 비싼데 보험료가 없어서 순위가 뒤집힌다.

## 4. 인코텀즈 비용 귀속

**FOB · CIF 둘만 다룬다.** EXW·DDP 를 정직하게 계산하려면 우리가 받지 않는 입력이 필요하다 —
DDP 는 **HS 코드**(EU TARIC 조회), EXW 는 **공장 주소**(수출지 내륙운송). 넓게 지원하는 척하며
배율로 때우느니 두 개를 근거 있게 계산하는 편이 낫다.

| 인코텀즈 | 매수인이 직접 지출 | 매도인 부담(상품가에 포함되어 청구) |
|---|---|---|
| **FOB** | 해상운임 · 탄소비용 · 전쟁위험보험료 | 수출통관 · 수출지 내륙운송 · 본선 적재 |
| **CIF** | **없음 (0)** | 수출통관 · 해상운임 · 탄소비용 · 적하보험 |

```
매수인 부담 = Σ(해당 인코텀즈에서 매수인이 내는 항목)
총비용     = 운임 + 탄소 + 전쟁위험 + 적하보험
매도인 부담 = 총비용 − 매수인 부담
```

### 4-1. 탄소비용은 왜 운임을 따라가나

배출권 **제출 의무자는 화주가 아니라 선사**다(EU ETS 지침 **Art.3gb**). Art.3gc 는 계약상
다른 주체가 연료·운항 책임을 지더라도 **선사가 제출하고 그 비용을 상환받는다**고 정한다.
즉 화주에게는 **운임 할증(ETS surcharge)** 으로 전가된다.

따라서 부담 주체는 인코텀즈가 직접 정하는 게 아니라 **"해상운임을 누가 내느냐"** 가 정한다.
운임과 함께 움직인다. — 이 논리는 앱의 규정 검색에서 원문 조문으로 확인된다.

### 4-2. 적하보험료 (CIF 전용)

```
적하보험료 = (화물가액 + 해상운임 + 탄소비용) × 110% × 0.15%
```

- **110%** — 실무 관행상 CIF 가액의 110% 를 부보한다
- **0.15%** — 업계 통용 범위(0.05~0.3%)의 **중앙값**. **이 모델에 남은 유일한 가정치다**
- **화물가액이 없으면 계산하지 말고 "입력 필요"로 표시하라.** 임의 값으로 채우면
  조용한 오답이 된다. 못 하는 건 못 한다고 표시한다.

## 5. 화물 단위 배율

`mult` = 기본운임 배율, `unit` = 탄소·전쟁위험보험료 산정 배율. **둘은 다른 값이다.**

| 유형 | 옵션 | mult(운임) | unit(탄소·보험) |
|---|---|---|---|
| 컨테이너 | 20ft | 1 | 1 |
| | 40ft | 1.8 | 2 |
| | 40ft HC | 1.9 | 2.1 |
| 완성차(PCTC) | 세단/소형 100대 | 100 | 100 |
| | SUV 100대 | 150 | 150 |
| | 대형 SUV·트럭 100대 | 220 | 220 |

> ⚠ **PCTC 는 반드시 100대분으로 세워라.** `unit` 을 1(=1 CEU)로 두면 100대분 탄소비용이
> 1대분으로 계산되어 **100배 과소**가 된다. 실제로 그 버그 때문에 "완성차 100대"와
> "20ft 컨테이너 1개"의 총비용이 $3,023 으로 **완전히 같게** 나왔다.
> `mult` 만 고치고 `unit` 을 안 고치면 운임 대비 탄소비용이 100배로 뒤틀린다 — **둘 다** 고쳐야 한다.

## 6. 항로 데이터

| 키 | 이름 | 상태 | 리드타임 | 기준운임 | 참고거리 | 실계산 거리 |
|---|---|---|---|---|---|---|
| A | 싱가포르 경유 | `limited` | 32일 | $2,840 | 11,400nm | **11,259nm** |
| B | 홍해 직항 | **`blocked`** | 25일 | $2,950 | 11,200nm | 11,259nm |
| D | 콜롬보 경유 | `limited` | 35일 | $2,900 | 11,700nm | **11,317nm** |
| C | 희망봉 우회 | **`best`** | **52일** | $3,200 | 14,500nm | **14,549nm** |

**상태 3종의 의미**

- `best` (추천) — 실행 가능. 추천 후보에 든다
- `limited` (제한적) — 숫자상 더 싸도 **실제로 배를 못 구할 수 있다.** 추천 후보에서 뺀다
- `blocked` (운항 불가) — **총비용을 만들지 않는다**

> A·D 를 `limited` 로 둔 이유: 바브엘만데브는 피하지만 **같은 홍해·수에즈 권역**이라
> 홍해 사태 이후 대형선이 몇 달째 피하고 있다. 다만 "완전히 막혔다"는 확증은 없어
> `blocked` 로 단정하지 않았다 — **불확실한 것을 확실한 것처럼 말하지 않는다.**

**C 의 52일 = 희망봉 우회 42일 + 항만 혼잡·대기 버퍼 10일.**
업계 분석의 +10~20일 중 상단을 쓴 것이다. 42 에 20 을 또 더하면 우회분 이중계상이 된다.

**추천 선정 규칙**

```
후보 = 상태가 best 인 것만
  (전부 limited/blocked 인 극단적 조건이면 blocked 만 제외해 빈 화면을 막는다)
후보 중 납기 충족하는 것 → 그중 총비용 최저 = 추천
납기 충족이 하나도 없으면 → 후보 전체에서 총비용 최저
```

> **`limited` 를 후보에서 빼는 것이 이 규칙의 요지다.** limited 는 숫자상 더 싸도 실제로
> 배를 못 구할 수 있다. 안 빼면 "가장 싼 경로"가 아니라 **"실행할 수 없는 경로"** 를 권한다.
> 현재 조건에서 이걸 안 지키면 추천이 A 싱가포르($2,916)로 나오고, 제품의 명제가 무너진다.

**정렬과 순위 배지**

```
표 정렬  = 총비용 오름차순 → blocked 를 맨 뒤에 붙인다
순위 배지 = blocked 를 뺀 나머지에만 1,2,3… (blocked 는 "—")
와플 기준 = 실행 가능한 항로 중 최대 총비용
```

**적용 순서** — 이 순서를 바꾸면 값이 달라진다

```
1) 거리 확정      실계산값이 있으면 그것, 없으면 참고거리 × 항구 비례계수
2) 배출량         거리 → 단위당 tCO2
3) 탄소비용       × 적용범위 0.5 × EUA 시세 × 단위배율 → EUR → USD
4) 운임           항로 기준운임 × 운임배율
5) 전쟁위험보험료  선체가치 × 단위배율 × 항로요율
6) 인코텀즈 귀속   3~5 를 매수인/매도인으로 배분 (+CIF 적하보험)
7) 총비용         blocked 면 null, 아니면 합계 반올림
8) 납기 역산      §8
```

## 7. 항로 거리와 지도

거리는 가정치가 아니라 **계산값**이다. 오픈소스 해상 항로망 라이브러리(Eurostat marnet 기반)를
쓰면 대권거리가 아닌 **실제 항로망**을 따라 계산되고, 통과 지점을 금지할 수 있다.

| 항로 | 경유지 | 통과 금지 |
|---|---|---|
| A | 싱가포르 | 없음 |
| B | 없음(직항) | 없음 |
| D | 싱가포르 → 콜롬보 | 없음 |
| C | 없음 | **수에즈 · 바브엘만데브 · 파나마** |

> ⚠ **파나마를 반드시 함께 막아라.** 수에즈·바브엘만데브만 막으면 라우터가
> **태평양 → 파나마**로 질러가서 "희망봉 우회"가 희망봉을 안 지난다.
> 지도에서 선이 삥 도는 것으로 드러났다.

> ⚠ **지도는 거리 계산이 돌려준 좌표를 그대로 그려라.** 거리는 계산값인데 선은 손으로 찍은
> 경유지를 그리면 둘이 따로 논다. 실제로 그래서 지도만 이상한 길로 갔다.
> 태평양을 건너는 경로는 경도 unwrap 처리를 해야 선이 지도를 가로지르지 않는다.

## 8. 납기 역산 (문전-문전)

```
전체 리드타임   = 출발측 육상(9) + 해상(항로별) + 도착측 육상(4)
운송 소요       = 해상 + 도착측 육상            ← 역산에 쓰는 값
최대 선적 가능일 = 납기일 − 운송 소요            (달력일)
여유일수        = 최대 선적 가능일 − 오늘        (달력일, 음수면 초과)
납기 충족       = 여유일수 ≥ 0
```

> **선적 전 구간(9일)은 역산에서 빼지 않는다.** 그건 "언제까지 생산을 시작해야 하는가"를
> 정하는 값이지 배에 싣는 시점을 앞당기지 않는다. 그래서 65일이 아니라 **56일**로 역산한다.
> 헷갈리기 쉬운 자리다 — 65로 빼면 최대 선적일이 9일 이르게 나온다.

### 8-1. 달력일과 영업일을 섞지 마라

| 용도 | 단위 |
|---|---|
| 리드타임 · 역산 · 도착일 | **달력일** |
| "N영업일 뒤" 표기 · 리스크 지평(T) | **영업일**(주말 제외) |

> ⚠ 영업일은 **실제로 세어라.** 예전에 화면마다 다르게 셌다 — 한쪽은 `달력일 × 5/7`
> 근사로 12일, 다른 쪽은 실제로 세어 11일. **같은 기간을 두 숫자로 말하면 어느 쪽도
> 못 믿는다.**

> ⚠ 날짜를 문자열로 만들 때 **UTC 변환을 타지 마라.** 자정 근처에서 하루가 밀린다
> (KST 자정 → UTC 전날 15시). 로컬 연·월·일을 직접 조립하라.

| 구간 | 일수 | 성격 |
|---|---|---|
| 생산·포장 (PCTC 는 생산·PDI검사) | 5 | **업계 평균 가정값** |
| 내륙운송(출발) | 2 | **가정값** |
| 수출통관 | 2 | **가정값** |
| **해상운송** | 항로별 (C=52) | 계산값 |
| 수입통관 | 2 | **가정값** |
| 내륙운송(도착) | 2 | **가정값** |

C 기준 총 **65일** (13 + 52).

> ⚠ **납기는 항구 도착이 아니라 창고 입고 기한이다.** 도착측 4일(수입통관 2 + 내륙 2)을
> 빼먹으면 역산이 **4일 낙관적**이 된다. 실제로 그 버그 때문에 경로 추천 탭은

가정값 구간은 **화면 각주에 "업계 평균치 기반 가정값"이라고 반드시 표기**한다.

## 9. 리스크 엔진 — 예측이 아니라 분포

**이 엔진은 EUA 가격을 예측하지 않는다.** 예측 가능한 것은 방향이 아니라 **변동성**이다
(변동성 군집). 그래서 중심은 현재가에 두고 **분포**만 계산한다.

### 9-1. 변동성

```
EWMA 일간 변동성:  v(t) = λ·v(t−1) + (1−λ)·r(t)²,   r = ln(P(t)/P(t−1))
일간 변동성 σ = √v ,   연율 변동성 = σ × √252
```

- **λ = 0.94** (RiskMetrics 표준값)
- 추정 창은 최근 **260 거래일**이면 충분하다. EWMA 유효 기억이 약 17거래일이라
  더 길게 잡아도 값이 거의 안 변한다
- ⚠ **1,728일은 "추정 창"이 아니라 "검증 표본"이다.** 각주에 두 개를 뭉뚱그려 쓰면
  사실과 달라진다(실제로 그렇게 썼다가 고쳤다)

### 9-2. T영업일 뒤 가격 구간

```
σ_T   = σ × √T
중앙   = S × exp(μT)
분위수 = S × exp(μT + Φ⁻¹(p) × σ_T)
        p = 0.025 / 0.10 / 0.90 / 0.975  →  lo95 / lo80 / hi80 / hi95
```

- μ = 0 이면 **중앙값**이 현재가다. 산술 기대값은 로그정규라 약간 위다(h=14 에서 +0.24%) —
  그래서 화면은 "기대값"이 아니라 **"중앙선"** 이라고 부른다. 이 단어를 바꾸지 마라
- μ 는 **외부 예측을 받는 선택 입력**이다. 사내 예측을 그대로 꽂는 진입점

### 9-3. 첫 통과 확률 (목표가 도달)

```
b  = ln(목표가/현재가) − 0.5826 × σ        ← 이산감시 보정
P  = Φ((b−μT)/σ_T) + exp(2μb/σ²)·Φ((b+μT)/σ_T)
```

- **0.5826 = Broadie-Glasserman-Kou 이산감시 보정계수.** 일별 종가만 관측하므로 필요하다.
  **빼면 접촉확률이 계통적으로 과대추정된다**(검증 시 평균 0.362 vs 실제 0.290)
- μ=0 이면 두 항이 같아져 무드리프트 식 `2Φ(b/σ_T)` 로 정확히 환원된다
- 목표가 ≥ 현재가면 즉시 1
- 몬테카를로 40만 경로로 대조 검증 완료(최대오차 0.013, 평균 0.005)

### 9-4. 선대 예산 리스크

```
과금대상 = 연간 배출량(tCO2) × ETS 적용범위(0.5)
최악가   = 현재가 × exp(Φ⁻¹(0.95) × σ × √252)
초과분   = 과금대상 × (최악가 − 현재가)
```

### 9-5. 외부 예측 → 드리프트 환산

```
μ(영업일당) = ln(1 + 변화율%/100) ÷ T
```

> ⚠ 변화율에 **−100 이하가 들어오면 ln(0 또는 음수)** 라 −Infinity/NaN 이 나오고
> **화면 전체가 NaN 이 된다**(도달확률 "NaN%", 구간 "NaN ~ NaN", 금액 "$NaN" — 실제로 재현됐다).
> **−99.9% 에서 잘라라.**

### 9-6. 검증 결과 — 이대로 말할 것

| 지표 | 값 |
|---|---|
| 워크포워드 표본 | **1,728일** (2019-09 ~ 2026-07) |
| 80% 구간 실제 포함률 | 80.2 / 81.1 / **82.3** / 84.2 / 77.8 % (h=5/10/14/21/63) |
| 95% 구간 실제 포함률 | 93.8 ~ 95.6 % |
| 방향 예측 | **AIC 24회 재학습 전부 랜덤워크 선택** |
| 보정오차 ECE | **0.0392** — 기후값 기준선 0.0294 **보다 나쁘다** |

> ECE 를 숨기지 마라. **한계로 먼저 밝히고 "확률은 보조 지표로만 쓴다"고 말하는 편이
> 강하다.** 초기에 0.0221 로 적었던 것은 유리한 부분표본에서 뽑은 값이었고, 전체 표본
> 기준으로 바로잡았다.

## 11. 실시간 값 — 하드코딩하지 마라

| 값 | 출처 | 갱신 |
|---|---|---|
| EUA 시세 | Yahoo Finance `CO2.L` (SparkChange Physical Carbon EUA ETC) | 30분 캐시 |

- 환율 **1.08 하드코딩은 금방 낡는다.** 실측 1.1548 대비 6.5% 낮았고 탄소비용 USD 환산이
  그만큼 과소계상됐다. API 실패 시에만 쓰는 **폴백**으로 두고, 화면 각주가
  "실시간" / "고정(폴백)"을 구분해 말하게 하라
- 각주는 **함수(또는 getter)로 만들어라.** 문자열 상수로 두면 모듈 로드 시점의 폴백 값이
  그대로 굳어서, 실시세를 받아와도 각주만 옛 숫자를 계속 말한다
- 조건: 환율 API 는 화면에 출처 표기 필요 —
  `Rates By Exchange Rate API` (https://www.exchangerate-api.com)
- **EUA 시세를 갈아끼울 때 변동성은 다시 계산하지 마라.** σ 는 검증된 값이다.
  바뀌는 것은 현재가와 기준일뿐이다
- **등락률도 같은 응답의 값을 써라.** 가격만 실시세로 바꾸고 등락률은 정적 스냅샷을 쓰면
  티커가 자기 값과 어긋난다(화면 `▼1.2%` vs 실제 `+1.77%` — 실제로 그랬다)
