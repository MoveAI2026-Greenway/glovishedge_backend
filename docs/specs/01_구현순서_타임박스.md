# 구현 순서와 타임박스

**현장에서 가장 위험한 건 "다 만들려다 아무것도 안 되는 것"이다.**
아래는 우선순위다. 시간이 모자라면 **아래에서부터 버린다.**

---

## 0. 무엇이 이 제품을 이 제품이게 하나

심사위원이 30초 안에 봐야 하는 장면은 **하나**다.

> **운임 최저는 싱가포르($2,840)인데, 실제로 추천되는 건 희망봉($3,200)이다.**
> 운임만 보면 순위가 뒤집힌다. 그 차이를 만드는 게 탄소비용과 전쟁위험보험료다.

이 장면이 뜨면 나머지가 없어도 제품이다. 이 장면이 없으면 나머지가 다 있어도 데모다.
**그래서 T1 을 가장 먼저 만든다.**

---

## T1 — 반드시 있어야 한다 (없으면 제품이 아니다)

| # | 무엇 | 왜 |
|---|---|---|
| 1 | **총비용 3분해 표** — 4개 항로, 운임/탄소/보험 분리, 총비용 낮은 순 정렬 | 제품의 명제 그 자체 |
| 2 | **상태 배지** 추천 / 제한적 / **운항 불가** | 최저가 ≠ 실행가능. 이게 두 번째 명제 |
| 3 | **운항 불가는 총비용을 만들지 않음** (접힘·펼침 **양쪽**) | 안 지키면 제품이 자기 말을 뒤집는다 |
| 4 | **조건 입력** — 출발/도착·화물·인코텀즈·납기 | 없으면 정적 그림이다 |
| 5 | **행 펼침 = 계산 근거** (거리·적용범위·요율) | 검산 가능해야 신뢰가 생긴다 |

**T1 완료 판정**: [수용기준](11_수용기준.md) **F-1 · F-2 전부 통과**.
= [계산명세 §10 검산표](02_계산명세.md)의 4개 총비용이 화면에 그대로 뜨고,
추천이 A 가 아니라 C 이며, B 는 펼쳐도 금액이 없다.

> T1 은 **LLM 없이 전부 만들 수 있다.** API 키가 안 풀려도 T1 은 진행하라.

## T4 — 현장에서는 버려라

- **RAG 색인 새로 구축** — 원문 수집·조 단위 청킹·임베딩에 몇 시간이 든다.
  하려면 **문서 1건, 조문 20~30개**로 줄여 "동작 증명"만 하라
- **로그인·이메일 알림** — 인프라 대비 심사 임팩트가 낮다
- **영상·PPT 재제작** — 이미 있다
- **PCTC(완성차) 지원** — 컨테이너가 완성된 뒤에만 손대라. 단위 배율 함정이 있다
  ([함정 2](06_함정목록.md))

## 권장 순서 — 의존성 기준

```
① 상수·항로 데이터 하드코딩        ← 표가 뜨는 최단 경로
      ↓
② 계산부 (탄소 → 전쟁위험 → 합계)   ← 검산표로 즉시 확인
      ↓
③ 표 + 상태 배지 + 펼침            ← 여기서 T1 완료. 데모 가능
      ↓
④ 조건 입력 → 재계산 배선
      ↓
⑤ 인코텀즈 귀속        ⑥ 납기 역산        ⑦ 지도
      ↓
⑧ 실시세 연동 (EUA · 환율)         ← 폴백을 먼저 넣고 API 를 나중에 붙여라
      ↓
⑨ 리스크 엔진 → ⑩ AI
```

각 단계의 완료 조건은 [수용기준](11_수용기준.md)의 F 번호로 잡혀 있다 —
①② → F-1 · ③ → F-2 · ⑤ → F-3 · ⑥ → F-4 · ⑦ → F-5 · ⑧ → F-7 · ⑨ → F-6 · ⑩ → F-8.

### 왜 이 순서인가

- **거리를 먼저 하드코딩하라.** 항로망 라이브러리 연동은 ⑦ 에서 해도 된다.
  [검산표](02_계산명세.md)의 실계산 거리(11,259 / 11,317 / 14,549)를 상수로 박고 시작하면
  계산부를 즉시 검증할 수 있다
- **폴백을 먼저, API 를 나중에.** 환율·시세를 상수로 두고 화면을 완성한 뒤 갈아끼워라.
  API 부터 붙이면 키 문제로 화면 진행이 멈춘다
- **계산부를 화면보다 먼저.** 화면부터 만들면 숫자가 틀린 걸 늦게 안다

## 시간이 없을 때 지켜야 할 최소선

기능을 버리는 건 괜찮다. **아래는 버리지 마라.**

1. **못 하는 것을 못 한다고 표시한다.** 가정값은 "가정값"이라고 화면에 쓴다.
   화물가액이 없으면 보험료를 임의로 채우지 말고 "입력 필요"로 둔다
2. **LLM 이 숫자를 만들지 않는다.** 금액·확률은 엔진 값만 인용한다
3. **가격의 방향을 예측하지 않는다.** 구간과 확률만 말한다

이 셋은 구현량이 0 이고 **심사에서 가장 강한 부분**이다. 시간이 없다고 무너뜨릴 이유가 없다.
