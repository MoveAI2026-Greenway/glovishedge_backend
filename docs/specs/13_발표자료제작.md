# 발표자료(결과보고서) 제작 명세

현장 산출물 셋 중 **발표자료**다. 주최측 **양식 PPT** 를 채우는 형태이고, 양식 안내에
`PPT 발표용 초안이라 상정하고 작성` 이라고 적혀 있다 — **보고서이자 발표 덱**이다.

---

## 1. 양식이 요구하는 것

양식 원본은 **11장**이다. 그중 **2장(작성 안내)은 지침이지 제출물이 아니라** 뺀다.
결과 → **표지 + 8섹션 + 기타 = 10장**. "10장 내외 권장"과도 맞는다.

| 양식 | 우리 슬라이드 | 양식이 요구하는 항목 |
|---|---|---|
| 1 | **표지** | 아이템명 / 도전 그룹(참여기업명) / 팀명 / **팀원** / 역할 |
| 2 | *(뺀다)* | 작성 안내 |
| 3 | **1. 문제 정의** | 해결하려는 문제 · 문제 상황 · 개선점 · 근거 |
| 4 | **2. 아이템 개요** | 서비스·아이디어 소개 · 수행 과정 · 착안점 |
| 5 | **3. 서비스 구성도** | 사용자 → 서비스 → AI → 결과 도식 + 기술스택(Frontend / Backend / DB / AI Model) |
| 6 | **4. 서비스 화면 ①** | 화면 + 설명 및 사용자 흐름(UI/UX 관점) |
| 7 | **5. 서비스 화면 ②** | 화면 + 설명 및 사용자 흐름 |
| 8 | **6. 주요 기능** | 각 기능의 역할과 사용자 가치 |
| 9 | **7. 모델 및 프롬프트** | 사용 모델 · **선택 이유** · 프롬프트 설계 · AI 역할 · **입출력 예시** |
| 10 | **8. 기대효과 및 개선점** | 정량·정성 효과 · 적용 가능 분야 · **한계점** · 향후 개선 |
| 11 | **기타** | 추가 화면 · 시나리오 · 참고자료 |

**캔버스는 10 × 7.5 인치(4:3)** — 양식과 같아야 한다. 16:9 로 만들면 양식과 안 맞는다.

> **GitHub 링크와 데모영상은 별도 제출**이다. 덱 안에 넣되, 그것으로 제출을 갈음하지 마라.

---

## 2. 표지 — 여기서 감점이 잘 난다

양식이 요구하는 건 **팀원 이름**이지 인원수가 아니다.

| 항목 | 값 |
|---|---|
| 아이템명 | GlovisHEDGE |
| 도전 그룹 | 현대글로비스 |
| 팀명 | GREENWAY (5인) |
| **팀원 · 역할** | **천송이**(팀장·기획/발표) · **김민태**(AI) · **최희원**(개발) · **김희원**(디자인/개발) · **김선우**(데이터분석/발표) |
| 제출일 | 제출 당일 |
| 데모 | 게이트웨이 URL |

> "기획·발표 1 · 개발 2 …" 처럼 **인원수만 적으면 요구사항 미충족**이다.
> 발표자 노트에 "제출 직전 채워 넣을 것"을 남겨두는 것도 사실상 placeholder 다.

## 3. 슬라이드별 채울 내용 — 이 제품의 경우

### 1. 문제 정의

- 상단 값 카드 3개: **전쟁위험보험 요율 0.75%** / **EU ETS 제출 100%** / **해상운송비 중 탄소비용 최대 19%**
- "지금 부산 → 함부르크에서 실제로 벌어지는 일" 4줄 — 봉쇄 → 최저가가 못 쓰는 항로 →
  실제 실을 수 있는 건 희망봉 **+$370(12.7%)** → **운임만 비교하면 판단이 통째로 뒤집힌다**
- 하단 강조 박스: 화주가 답을 못 얻는 질문 3개

### 2. 아이템 개요

- 3열 카드: ① 총비용 3분해 ② 방향이 아니라 구간 ③ 근거가 남는 결정
- **"수행 과정에서 바뀐 것"을 반드시 쓴다** — 양식이 "수행 과정·착안점"을 요구한다.
  우리 경우: 예측 제품 → 구간 제품으로 **주장을 접은 것**, "최저가 = 추천" 전제가 깨진 것,
  납기가 항구 도착이 아니라 창고 입고인 것

### 3. 서비스 구성도

- 가로 흐름: 화주 → Frontend → Backend → 결과
- 아래 3박스: **리스크 엔진(숫자)** · **RAG 색인(검색)** · **LLM(설명만)**
- 기술스택 표 — Frontend / Backend / DB / AI Model / 외부 API / 오프라인
- 각주: **LLM 은 금액·확률을 만들지 않는다**

### 4·5. 서비스 화면 ①②

- ①: KPI 띠 + 비교표 + 사용자 흐름 + 지도
- ②: 팬차트 + 리드타임 + AI 어시스턴트
- 양식이 **"사용자 흐름(UI/UX 관점)"** 을 요구한다 — 화면만 붙이지 말고 흐름을 글로 쓴다

### 6. 주요 기능

6개 카드: 총비용 3분해 · 구간/도달확률 · 납기 역산 · 규정 근거 검색 · **인코텀즈 비용 귀속** ·
목표가 도달 알림

### 7. 모델 및 프롬프트

- 모델 3종과 **선택 이유**(기본 / 폴백 / 임베딩)
- **프롬프트 설계 세 제약**: 숫자 생성 금지 · 선택지 목록 주입 · 인용 없으면 답하지 않음
- **입출력 예시 1건**을 실제로 넣는다(양식 요구사항)

### 8. 기대효과 및 개선점

- 정량 / 정성 / 적용 가능 분야
- **한계점을 숨기지 마라** — 방향 예측 불가(AIC 24/24), **ECE 0.0392로 기준선보다 나쁨**,
  벙커유 프록시, 정시운항율 가정값
- 향후 개선 계획

### 기타

- 검증 근거 값 카드 4개 + 검증 방식 + **데이터 출처 표**

## 4. 레이아웃 규칙 — 실제로 틀렸던 것들

### 이미지 종횡비

발표자료 라이브러리는 폭·높이를 **둘 다** 주면 프레임에 맞춰 **늘린다.**
세로로 긴 비교표(0.93)를 가로 프레임(1.61)에 넣어 **가로로 72% 퍼진** 채 만들어질 뻔했다.

> **한 축만 지정하고 나머지는 원본 픽셀비로 계산하라.**
> 세로로 긴 캡처는 **높이 기준**으로 맞춰 좌측에 세우고 오른쪽을 글로 채운다.

### 캡처

- **뷰포트 고정 · 기능 단위**로 찍는다(`fullPage` 금지)
- 캡처 후 **실제 픽셀 크기를 출력**해 세로 1500px 넘으면 잘못된 것
- **우측 상시 패널은 넓은 화면에서만 보인다** — 1920 뷰포트로 찍어야 나온다

### 폰트·색

- 한글 폰트는 **Office 기본 탑재 폰트**를 쓴다(심사 PC 에서 안 깨지게)
- 색은 **제품 화면과 같은 팔레트** ([화면명세 §2](04_화면명세.md)).
  보고서와 데모가 따로 놀면 같은 팀 작업으로 안 보인다

## 7. 덱과 영상과 화면이 같은 말을 하는가

마지막에 **셋을 나란히 놓고** 대조하라. 각각은 맞는데 합치면 모순인 상태가 실제로 있었다.

| 대조 | 확인 |
|---|---|
| 덱 ↔ 화면 | 추천 항로·금액·거리가 같다 |
| 덱 ↔ 영상 | 낭독 수치가 덱 수치와 같다 |
| 덱 ↔ 덱 | 캡처에 찍힌 숫자와 본문 숫자가 같다 |
| 주장 | 셋 다 "방향 예측 안 함"으로 일치한다 |

> 실제 사고 예: 소개 화면은 "싱가포르 $2,684 추천", 앱은 "희망봉 $3,029 추천" —
> **첫 화면에서 읽은 결론이 다음 화면에서 뒤집혔다.**
> 또 다른 예: 옛 덱이 "2주 예측해서 **최적 선적일 권고**"라고 말하는데 제품은 예측을 접었다.
> 그 덱은 폐기했다.
