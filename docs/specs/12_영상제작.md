# 영상 제작 명세

현장 산출물은 셋이다 — **데모 앱 · 영상 · 발표자료**. 이 문서는 그중 **영상**이다.

완성본 기준: **1920×1080 · 30fps · 2분 54초 · h264/aac**.
영상은 앱이 T2 까지 돌아가야 찍을 수 있다. **앱을 먼저 만들고 영상은 마지막에.**

---

## 1. 서사 구조 — 데모 화면만 이어붙이지 마라

PPT 와 **같은 순서**를 따른다: 문제정의 → 솔루션 → 데모 → 기대효과.

| 씬 | 역할 | 형태 | 길이 |
|---|---|---|---|
| 0 | 문제 제기 | **생성 이미지 3컷** | 15.7초 |
| 1 | 문제 정량화 0.6% → 1.4% | 배경 + 직접 그린 숫자 | 10.3초 |
| 2 | 해법 + 경로 추천 | 화면 녹화 | 28.4초 |
| 3 | 비용 3분해 | 화면 녹화 | 11.8초 |
| 4 | 인코텀즈 귀속 | 화면 녹화 | 12.5초 |
| 5 | 선적 시점 + **선대 예산 리스크** | 화면 녹화 | 27.4초 |
| 6 | 공급망 일정 | 화면 녹화 | 16.1초 |
| 7 | AI 비교 · 근거 리포트 | 화면 녹화 | 21.5초 |
| 8 | 기대효과 | 카드 모션 | 7.7초 |
| 9 | 클로징 | **엔드카드** | 6.1초 |

**앞 두 씬을 화면 녹화로 하지 마라.** 문제를 화면으로 보여주면 "기능 소개"가 되고,
심사위원이 왜 이 제품이 필요한지 모른 채 표를 보게 된다.

**규칙**

- **한 씬 30초 초과 금지**
- 총 길이 **3분 이내**
- 낭독 중 화면은 계속 움직인다(정지 화면 금지)
- 씬 꼬리 여백 1.2초 · 숫자가 빽빽한 씬(3·5·7)은 1.5초
- 스크롤 목표는 **자막바(약 150px)를 피해** 잡는다

### 낭독 원고의 규칙

- **숫자는 한글로 적어라.** `$370` → "삼백칠십 달러". 엔진이 기호를 잘못 읽는다
- **마크다운 강조(`**`)를 TTS 에 넘기지 마라.** 전처리에서 제거한다
- **"석 달"처럼 지평을 빼먹지 마라.** $296.4M 은 **3개월** 값이다. 지평 없이 말하면
  연간 값으로 오해된다(1년은 $745.8M · 12.9배로 완전히 다르다)

## 3. TTS

| 항목 | 값 |
|---|---|
| 엔진 | Google Cloud Text-to-Speech **Chirp 3: HD** |
| 보이스 | **`ko-KR-Chirp3-HD-Kore`** (여성) |
| 속도 | `speakingRate` **0.96** |
| 문장 간 텀 | **0.6초** |
| 실측 낭독 속도 | 약 **5.07자/초** (금액 문장은 4.9자/초로 더 느리다) |

**반드시 지킬 것**

- **문장을 통으로 한 번에 생성하지 마라.** 문장별로 따로 생성해 **무음 0.6초를 끼워** 붙인다.
  통으로 만들면 문장이 붙어 읽혀 "너무 빠르다"는 말이 나온다
- 부수 효과가 핵심이다 — 문장별로 만들면 **문장별 실제 시작·끝 시각**이 나온다.
  자막과 화면 큐를 **글자수 비례 추정이 아니라 이 실측값**으로 붙인다
- 생성 후 **길이를 실제로 재서** 타임테이블에 넣어라. 엔진·보이스·텀에 따라 다르다
- **보이스를 바꿀 땐 성별부터 확인하라.** 속도만 보고 고르면 화자 성별이 바뀐다
  (실제로 남성 보이스를 골랐다가 지적받았다)
- ⚠ **같은 문장도 호출마다 길이가 달라진다**(실측: 4.77초 → 5.76초).
  그래서 **바뀐 씬만 재생성**해야 한다. 전 씬을 다시 만들면 안 바뀐 씬의 큐까지 흔들려
  재녹화가 필요 없는 씬도 다시 찍어야 한다
- ⚠ 재생성 전 **그 씬의 기존 음성 파일을 먼저 지워라.** 이어받기가 옛 음성을 새 자막에 붙인다

## 4. 화면 녹화 — 여기서 가장 많이 틀린다

### 4-1. 낭독 타임스탬프를 큐로 쓴다

**손으로 대기시간을 넣고 나중에 배속으로 길이를 맞추지 마라.** 그러면 씬 **총길이만** 맞고
내부 대응은 깨진다 — 실제로 "홍해까지 막혔습니다"에서 엉뚱한 섹션이 나갔다.

```
문장별 실측 시작시각(startMs) → 캡처 스크립트가 큐로 읽는다
녹화 시작 시점과 큐 시계 t0 의 오프셋을 기록 → 그 지점부터 잘라낸다
후처리 배속은 쓰지 않는다
```

**문장을 지우거나 넣으면 큐 인덱스를 함께 당겨라.** 3씬 첫 문장을 지웠는데 인덱스를
그대로 뒀으면 "삼백칠십 달러"에서 화면이 아직 콜롬보 행에 있었다.

### 4-2. 녹화 전 강제 검사 — 실패하면 중단

프런트만 띄우고 API 를 안 띄워 **"분석에 실패했습니다" 에러 화면을 그대로 녹화한 사고**가 있었다.

- [ ] 빌드본을 서빙하는 상태인가 (개발 서버 아님)
- [ ] `/api/eua` · `/api/fx` · `/api/sea-distance` · 항로비교 API 전부 **200**
- [ ] 초기 조건: 부산항 → 함부르크항 · **FOB** · 20ft · 납기 2026-10-05 · 필터 전부 해제
- [ ] 낭독 수치 = 촬영 시점 화면값 ($3,286 · +$370 · 1.4% · $296.4M · 11.6배)
- [ ] 뷰포트 **1920×1080**

**핵심 숫자는 문자열로 검사해서 없으면 녹화를 중단하라.** 실시간 시세가 움직이면
다음 재촬영 때 자동으로 걸린다.

### 4-3. LLM 호출은 녹화 시계 밖에서

왕복이 10초 안팎이라 씬 안에서 기다리면 **스피너가 문장 두 개를 먹는다.**
`prepare` 훅에서 t0 이전에 호출을 끝내둔다.

⚠ **AI 배너 문구는 호출마다 달라진다.** 낭독과 취지가 맞는지 **프로그램으로 판정**한 뒤
녹화에 들어가라(예: "제한"·"리스크"·"선택" 계열 단어 포함, 첫 등장이 문장 앞쪽).
안 맞으면 다시 호출하고, 3회 실패하면 배너 없이 본문 중심으로 찍어라.

⚠ **짧은 페이로드로 API 를 직접 때리면 다른 결론이 나온다**(실측: "상태상 우열은 없으므로
A가 유리합니다"). 앱이 실어 보내는 **긴 상태 사유**가 있어야 낭독과 맞는 결론이 나온다 —
**화면에서 호출한 응답을 캐시해서 써라.**

### 4-4. 화면 확대

확대는 `html` 이 아니라 **`#root`(앱 루트)** 에 건다. `html` 에 걸면 요소 실측 좌표(시각
좌표)와 포털 드롭다운의 fixed 위치(줌 좌표)가 어긋나 패널이 1.33배 밀리고 클릭이 막힌다.
인코텀즈 씬이 드롭다운을 카메라 안에서 여는 유일한 씬이라 이게 전제조건이다.

### 4-5. 세로로 긴 카드

가운데 정렬하면 **핵심 숫자가 화면 밖으로 밀린다.** 선대 예산 카드(≈900px)는 상단 정렬이어야
`$296.4M` 이 보인다. 스모크 촬영으로 먼저 확인하라.

## 5. 엔드카드 — 마지막 씬은 제품 화면이 아니다

제품 화면으로 끝내면 "끊긴" 느낌이 난다.

- 구성: **로고 · 한 줄 · 팀명 · URL**
- URL 은 **게이트웨이 주소**(배포 주소가 바뀌어도 안 깨진다)
- **자막을 띄우지 마라** — 낭독 문장과 화면 문구가 같은 말이면 두 번 보인다
- 낭독이 끝난 뒤 **3~4초 머문 뒤** 페이드아웃
- 렌더 후 **그 구간 프레임을 반드시 뽑아 눈으로 확인**하라

---

## 6. 자막

- 문장별 **실측 시작·끝 시각**으로 붙인다(글자수 비례 추정 금지)
- 하단 중앙, 반투명 어두운 박스 + 흰 글씨
- 엔드카드 구간만 **자막 없음**

---

## 7. 렌더 후 검수 — 생략 금지

**전 문장의 프레임을 뽑아 화면과 낭독을 1:1 대조한다.**

| 확인 | 통과 조건 |
|---|---|
| 각 문장 시작 시각의 프레임 | 낭독 내용과 화면이 같은 것을 가리킨다 |
| 2씬 운항 불가 | B 행 펼침에 **금액이 없다** |
| 3씬 | `+$370 (12.7%)` 가 보인다 |
| 4씬 CIF | 매수인 **$0** |
| 5씬 | `$296.4M` · `11.6배` · **3개월 토글**이 함께 보인다 |
| 9씬 엔드카드 | 자막 없음 · URL · 홀드 후 페이드아웃 |
| 전체 | 큐 초과 경고 0 · 후처리 배속 0 |

어긋난 문장이 있으면 **그 씬만 재녹화**하고 다시 렌더한다. 전체를 다시 만들지 마라.

## 8. 제작 순서

```
① 나레이션 원고 확정 (수치는 화면에서 실제로 읽어 확인)
② 문장별 TTS 생성 + 무음 삽입 → 문장별 실측 시각표
③ 앱 빌드 → 서버 기동 → API 헬스체크
④ 타임스탬프를 큐로 화면 녹화 (LLM 은 prepare 에서 미리)
⑤ 오프셋 잘라내기 (배속 없음)
⑥ 씬 합성 + 자막 + 엔드카드 렌더
⑦ 배경음악 믹스
⑧ 전 문장 프레임 대조 → 어긋나면 해당 씬만 ④부터 다시
```

### 시간이 없으면

- **씬 0·1(생성 이미지)을 정적 카드로 대체**해도 된다. 서사만 유지하면 된다
- **씬 5·7 을 버려라.** 2·3·4·6·8·9 만으로도 명제는 전달된다
- **엔드카드는 버리지 마라.** 없으면 끊긴 느낌이 난다

## 9. 마지막 점검

- [ ] 소스 화면 방향(가로)과 캔버스 방향이 **일치**한다
- [ ] 총 3분 이내
- [ ] 낭독 수치와 화면 수치가 전부 일치
- [ ] 엔드카드 URL 이 **게이트웨이 주소**
- [ ] 화자 성별·톤이 이전 영상과 같다(여성)
- [ ] 앱에 영상을 넣었다면 **길이 표기**가 실제와 맞다(플레이어는 내림 표시)
